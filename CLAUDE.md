# Virallink (ex-« Veille virale ») — notes pour Claude

Application web par abonnement (Flask) qui repère les Reels et carrousels Instagram/TikTok viraux de comptes à copier, les analyse (vidéo, transcription, slides) et les adapte à la niche de l'utilisateur avec Claude. Le propriétaire est francophone : code, interface, messages et commits en **français**.

## Lancer et tester
- `python app.py --demo --port 8000` : application complète avec données fictives (aucune clé API consommée). Sans clés dans `.env`, le mode démo est automatique.
- `python veille.py --demo` : moteur en ligne de commande.
- Pas de suite de tests : vérifier chaque changement en mode démo (inscription → assistant → analyse → galerie), sur ordinateur et à 390 px de large.
- Dépendance système : ffmpeg (avec libass). La lecture des commentaires a été retirée (coût Apify, peu utile).

## Architecture
- `app.py` : serveur, API JSON, file de tâches (une à la fois), veille automatique du lundi.
- `abonnements.py` : utilisateurs SQLite (`data/app.db`), formules (`plans.yaml`), quotas, Stripe sans SDK.
- Formule gratuite (`gratuit` dans `plans.yaml`) : tout nouveau compte y démarre (`abonnements.cree`), fin d'essai, résiliation ou impayé y rebasculent automatiquement (`abonnements.plan_effectif`). Elle comprend la boutique et les tendances de sa niche en lecture. Ses options (`ia`, `montage_reel`, `suivi_publications`, `sequences_emails`, `filigrane`, `mention_boutique`, `commission_boutique`, `comptes_perso`) se vérifient avec `reserve(u, option)` dans `app.py` ; une analyse y est un simple classement (`moteur.executer(classement_seul=True)`, plus proposé dans l'interface).
- `espace.py` : un dossier par client dans `data/espaces/<id>/` (config.yaml, historique, analyses, médias, suivi).
- `moteur.py` : orchestration d'une analyse (`executer`), adaptation unitaire, assistant (analyse du compte, hashtags).
- `collecte.py` (Apify ; Reels, carrousels, son utilisé), `video.py` (ffmpeg + Whisper), `suggestions.py` (comptes Instagram ou TikTok à copier proposés par Claude puis vérifiés par collecte, compte par compte ; TikTok : 12 candidats × 8 vidéos car sa collecte coûte ~30× plus cher), `banque.py` (images et vidéos libres de droits Pixabay ou Pexels, démo sans clé ; résultats reclassés par `_pertinence` : mots-clés `recherche` de la slide, écrits par Claude pour illustrer son texte, retrouvés dans la description de l'image), `commentaires.py`, `ia.py` (tous les appels Claude, sorties forcées par outil), `selection.py`, `apprentissage.py`, `decouverte.py`, `rapports.py`.
- `bibliotheque.py` : bibliothèque virale partagée, par niche (12 niches de `bibliotheque.yaml`, ~50 comptes chacune depuis le 10 novembre 2026 (liste doublée à la demande de Mohamed ; `ajoute_comptes_depart`, une fois au démarrage, fusionne les nouveaux comptes dans la liste de l'admin puis retire ceux que la vérification trouve introuvables ou privés, marqueur `etat()["comptes_depart_v2"]`), 120 préparations par jour (`MAX_PREPARATIONS`), listes modifiables dans l'admin → `data/bibliotheque/niches.json`). Instagram seulement. Une collecte par jour pour toutes les clientes (`actualise`, lancée par `_actualise_bibliotheque` dans `planificateur` à partir de 3 h, 2 tentatives max, tâche uid 0 dans `FILE` ; lecture plus profonde le lundi), historique par compte (`comptes.json`) pour mesurer son habitude, règle virale `juge` : 48 h à 3 mois, ≥ 3× la médiane du compte pour ce format, et Reel ≥ 30 000 vues + 3 % d'engagement, Carrousel ≥ 5 000 j'aime, Photo ≥ 10 000 j'aime (`REGLES`). Chaque publication virale est préparée une seule fois (`prepare` : slides ou images clés + transcription Whisper, dans `bibliotheque/media/<id>/`, 60 par jour), purgée après 3 mois. Côté clientes : niche devinée du profil (`devine_niches`, sans IA) ou choisie (`cfg["bibliotheque"]["niches"]`, 2 max, `choixNiche()`), veille du lundi qui puise dans la bibliothèque (`moteur.executer` : `posts_pour`, déjà jugées et préparées ; comptes perso en plus seulement avec l'option `comptes_perso`, coupée pour toutes les formules depuis le 10 novembre 2026, décision de Mohamed), vue gratuite « Tendances de ma niche » (`moteur.tendances`, analyse `tendances.json` hors historique, `/api/tendances`, onglet `S.source` dans la galerie, adaptations gardées). Galerie en 3 catégories Carrousels / Reels / Publications (`categorie`, `CATS`, `#f-cat`). Filtre « 🙈 Sans visage » (`#f-faceless`, `S.faceless`) : publications faceless repérées par `visages.py` (OpenCV YuNet, modèle `modeles/face_detection_yunet_2023mar.onnx`, local et gratuit ; visage ≥ 14 % de la largeur ; Reel : visage sur moins de 2 images clés ; carrousel/photo : aucune slide avec visage), `e["faceless"]` posé par `prepare` et rattrapé par `marque_faceless` (fin d'`actualise` et au démarrage, `_marque_faceless`), clé `etat()["visages"]` dans le cache des tendances. Admin : section « Bibliothèque virale » (coût par jour, comptes avec abonnés et nombre de virales, « Vérifier les comptes » = `verifie_comptes`, « Actualiser maintenant »). Démo : `demo.posts_bibliotheque` / `prepare_bibliotheque`.
- `studio.py` : studio de création (carrousels Pillow, Reels montés ffmpeg + libass avec hook et sous-titres Whisper, diaporamas, couvertures de Reel en 7 styles avec aperçu grille 3:4, package ZIP). Typographie : 81 polices en 7 styles (`STYLES_TYPO`, `_PLUS`), tailles du titre et du texte + casse par projet (`typo_reglages`, résolus par `_typo`/`typo_projet`) ; polices ajoutées figées en gras et nommées « VV … » pour libass. `studio_styles.py` : 108 styles de carrousel classés en 10 familles de couleurs (`FAMILLES`, `GABARITS` × `_PALETTES` → `MODELES` : fond texturé numpy/Pillow, couleurs, typo, numéro, surtitre, note manuscrite) choisis par `p["modele"]`, couleurs du titre et du texte par `p["couleurs_texte"]` (aussi hook et sous-titres des Reels), résolus dans `theme_de`. File de tâches séparée (`FILE_STUDIO`), quota `studio_par_mois`. Reel sans se filmer : choix « 🤳 Je me filme / 🎬 Une vidéo libre de droits » dans `choisirFormat(cle, videoBanque)` (si `banque`), bouton « Pas envie de te filmer ? » sous le script de la fiche (`data-studio-video`) : le projet créé ouvre aussitôt la banque de vidéos (`ouvreBanque(0, true)`, Pixabay).
- `voix.py` : voix off des Reels lue par Virall.ai. ElevenLabs en priorité (`ELEVENLABS_API_KEY`, modèle `eleven_multilingual_v2`, ~0,00018 $/caractère ; voix françaises natives prises dans leur bibliothèque `/v1/shared-voices` (les plus utilisées selon `RECHERCHE_ELEVEN`), ajoutées au compte une fois et mémorisées dans `data/voix_elevenlabs.json`, ou imposées par `ELEVENLABS_VOIX_FEMME|DOUCE|HOMME`), sinon OpenAI `gpt-4o-mini-tts` (`OPENAI_API_KEY`, jugée robotique en français par Mohamed). Coût ajouté à `ia._JETONS` donc à `usage.cout_usd`. `p["voix_off"]` (femme, douce, homme ; vide = aucune) et `p["texte_voix"]` (sinon `texte_du_script`). `studio.voix_du_projet` (réutilisée si texte et voix identiques : `voix.sig`) → `monte_reel` (son d'origine remplacé, sous-titres Whisper sur la voix) ou `monte_diaporama`. Interface `blocVoixOff`/`brancheVoixOff`, extraits `/api/studio/voix/<cle>.mp3` (`data/voix_exemples/`). Sans clé : option masquée ; démo : piste muette.
- Reel en plusieurs plans (« Une vidéo libre de droits ») : `studio.prepare_plans` (tâche « Choix des vidéos », `POST /api/studio/<sid>/plans`, option `montage_reel`) découpe la voix off en phrases (`decoupe_phrases`, 8 max), `ia.plans_reel` (modèle léger) écrit des mots-clés anglais par phrase, la banque fournit une vidéo par phrase assez longue (`MOTS_PAR_SECONDE`), rangée dans `p["plans"]` (`p["video"]` = 1er plan pour l'aperçu) ; `monte_plans` coupe chaque plan au prorata de sa phrase sur la durée de la voix, les assemble puis passe par `monte_reel`. Interface `blocPlans` (« Changer » → `ouvreBanque(0, true, plan)`, vidéos de la bonne durée en premier), `lancePlans` (lancé tout seul après l'écriture du script quand on choisit « 🎬 Une vidéo libre de droits », `S.plansApres`).
- `stories.py` : stories animées (projets du Studio de type `stories`, mêmes dossiers, envois de photos `/api/studio/<sid>/fichiers?slide=`, banque `ouvreBanque`, « Mes créations »). Écran « De quoi tu veux parler ? » : idées d'un toucher (`idees` de `/api/stories/options` → `_idees_stories` : `cfg["idees_stories"]` du compte, sinon tirées de ses produits et de sa niche). Assistant guidé une question par écran (`renduStoriesAssistant`, `S.stw`, `ETAPES_STW` : suite ou story seule → objectif (`OBJECTIFS`, 6 séquences de 5-6 rôles) ou modèle (`MODELES`) → sujet + produit de la boutique → effet (`EFFETS` : doux, dynamique, paillettes, néon, surligneur, machine à écrire, film, mot par mot, écrit à la main, compteur (le chiffre du titre grimpe), balayage (flou de mouvement), téléphone (photo dans un téléphone incliné, `_telephone`), notifications (une carte par ligne du texte, `_cartes_notif`) ou, si la cliente envoie ses propres captures de résultats (ventes, gains, messages ; `s["preuves"]`, 5 max par story, `POST/DELETE /api/stories/<sid>/preuves/<i>`, `ajoute_preuve`), ces captures mises en forme en cartes empilées (`_cartes_preuves`) : jamais de montant inventé ; aperçus CSS `.fx-*` ; aperçu fixe = image de fin de l'animation, `images_story(seulement=…)`) → couleurs (`PALETTES` + ma marque) → images banque ou miennes) ; textes par `ia.ecrit_stories` (titre, texte, recherche d'image, sticker conseillé et son texte ; option `ia`, file `FILE_STUDIO`) ; écran projet `renduStoriesProjet` (textes retouchables, image par story, effet et couleurs, aperçu fixe `/api/stories/<sid>/apercu/<i>`). Rendu `genere` : images Pillow 1080×1920 à 30 i/s envoyées à ffmpeg (`_encode`), 5 à 9 s par story selon le texte, ~10 s de calcul par story ; 1 création du Studio. Consignes libres à Virall.ai dans l'écran projet (« titre plus gros », « story 3 plus percutante »… : `POST /api/stories/<sid>/retouche` → `stories.retouche` → `ia.retouche_stories`, outil `OUTIL_RETOUCHE_STORIES`, appliqué par `applique_retouche` ; historique `p["retouches"]`) qui pilotent les textes, le mot en couleur (`mot`), l'effet par story, la durée, et les réglages `REGLAGES` (taille du titre et du texte, position, alignement, majuscules, durée, vitesse, intensité, voile des photos, signature @, ombre ; `reglages(p)`). Mises en page par story (`stories_formats.py`, `s["format"]` : note, magazine, scrapbook, conversation (« Messages »), verre (« Givré »), affiche, publication (« Post »), bento, soustitres (« Karaoké »), autocollants (« Étiquettes »)) : de vrais gabarits faits de calques animés (`C`, `_pose`), réduits jusqu'à tenir entre la barre d'Instagram et le sticker (`_compose`), qui remplacent l'effet de la story (`format_de` ; ignorés si la story a des `preuves`) ; l'écran projet en propose 5 par story, les mieux adaptées à son texte et à sa photo d'abord (`GET /api/stories/<sid>/formats` → `classe`, vignettes `/apercu/<i>?format=`, `cinq`, tuile « 5 autres ») ; « Virall.ai choisit » (`effet: "auto"` dans l'assistant ou puce Style → `formats_auto`/`choisis` : une mise en page différente par story) ; choisir un effet pour toutes les stories efface les mises en page (annulable). Aperçus : 2 calculs à la fois (`_APERCUS`), gardés par le navigateur grâce à une empreinte du contenu (`cleApercu`, `cleFormat`). Les stickers Instagram (sondage, lien…) ne s'incrustent pas : place laissée en bas et guide « où poser quel sticker » (écran + LISEZ-MOI du ZIP). API `/api/stories*`.
- `plan30.py` : plan de contenu de 30 jours (onglet Studio, `renduPlan30` dans `index.html`) : 8 carrousels en tunnel de vente (storytelling → éducatif → preuve sociale → vente, mardi et vendredi sur 4 semaines, `SEQUENCE`). Les publications de toutes les veilles sont regroupées par catégorie du tunnel d'après leur `type_contenu` (`TYPE_VERS_CAT`) et triées (adaptées, virales, carrousels, score) ; chaque case reprend la STRUCTURE de la meilleure publication de sa catégorie, jamais son texte ni ses images. Infos de vente données une seule fois par boutique (`plan30/brief.json`, `brief_<bid>.json` pour les boutiques suivantes ; l'offre se choisit parmi les produits de la boutique, `_produits_plan30`, un ou plusieurs (cases à cocher, `ids30`/`choisis30` : ids dans `produit_id` séparés par des virgules, liste `produits` « titre (prix) » ; plusieurs → lien vers la boutique et chaque carrousel de vente met en avant un seul produit, `_contexte_brief`) ; rien n'est pré-rempli : ce qui a déjà été répondu n'est pas reposé (`plan30.connu`/`complete` via `_brief30` : cible et « tu les aides à » de la création de la boutique, gardés dans `page["activite"]`, sinon cible et problèmes du profil ; écrans sautés par `deja30` sauf après « Modifier mes infos de vente », `S.p30Modif`); ensuite chaque nouveau plan s'ouvre directement sur le dernier écran : dates du mois) : offre, cible, problèmes, objections, témoignages réels seulement, histoire, ton) ; sujets des 8 cases écrits par `ia.ecrit_plan30`. Fabrication (`fabrique`) = projet du studio + `ecrit_textes` avec `p["consigne_plan"]` (passé à `IA.carrousel(tunnel=…)`) + banque d'images + `genere` ; 1 création au studio par carrousel. Quota `plans_30j_par_mois` dans `plans.yaml`. API `/api/plan30*`.
- `boutique.py` : boutique en lien dans la bio (page publique `/@pseudo`, thèmes et design, produits numériques, capture d'e-mails, kit média, statistiques). Produit « Vendre via un lien d'affiliation » (`externe`, affiliation ou plateforme de formation) : son bouton mène à `lien` via `/@pseudo/p/<pid>/ouvrir`, sans Stripe, et ne compte pas dans l'étape « activer les paiements ». Paiements via Stripe Connect sur le compte de chaque cliente (comptes Standard, paiements directs avec l'en-tête Stripe-Account, `connecte_stripe`/`session_achat` ; `BOUTIQUE_COMMISSION` en %, 0 par défaut) ; vente livrée au retour sur `/@pseudo/merci` et, en secours, par le webhook des comptes connectés `/api/stripe/connect/webhook` (`STRIPE_CONNECT_WEBHOOK_SECRET`, `checkout.session.completed` et `async_payment_succeeded`, `_livre` idempotent par session) ; achats simulés en démo. Données dans `data/espaces/<id>/boutique/`, pseudos uniques dans la table `boutiques`. Mises en page (`design.mise_en_page` : colonne, bento, magazine ; `_css_mise_en_page`) avec espacement, largeur de page et taille du texte ; 126 thèmes en 7 ambiances (dont Bento et Éditorial, allures `tuiles*` et `edito`). Chaque bloc est enveloppé par `_bloc_enveloppe` : largeur sur une grille de 6 colonnes (`largeur` : plein, deux_tiers, demi, tiers), `hauteur` (bento) et `style` propre (fond, texte, forme, bouton, taille, align, police). Blocs : lien, titre, texte, vidéo, produit(s), capture, kit, image, galerie, témoignages, FAQ, compte à rebours, bannière, séparateur, musique (`lecteur_musique`). Polices : une feuille Google Fonts par famille. Un bloc « lien » peut porter `produit` : le bouton mène alors à la page de paiement (`/@pseudo/l/<bid>` → `/@pseudo/p/<pid>?src=bouton`) ; raccourci « Bouton de paiement » dans la liste des blocs. Création rapide de toute nouvelle boutique (`A.rapide`, `etapesRapides`, lot 2 de l'audit) : « Quel est ton compte Instagram ? » → lecture du profil public (`POST /api/boutique/instagram` → `boutique_instagram.prepare` : photo, ses couleurs, nom, présentation, lien de la bio sauf agrégateurs, adresse libre ; file `FILE_STUDIO`, ~0,2 centime, `litInstagram` côté client, jamais bloquant : compte illisible, refus ou délai de 50 s → suite à la main) → « Voilà ta boutique » (vérifier, `cree`) → design → en ligne ; sans Instagram : nom + adresse sur le même écran → « J'aide … à … » (`phraseBio`, « Plus tard ») → logo (« Continuer sans logo ») → design. Offres, paiements, présentation se complètent ensuite (carte « Prochaine étape », dont « Écrire ma présentation » → `assistantPresentation`, mode `presentation`). Gardes de la lecture : adresse confirmée (sinon écran « Confirme ton adresse » dans le parcours ; exception décidée par Mohamed : une lecture par compte avant confirmation, ouverte par défaut, `INSTAGRAM_AVANT_CONFIRMATION=0` pour la couper), formule active et budget, `LECTURES_IG_PAR_COMPTE` (3/24 h), `LECTURES_IG_PAR_IP` (5/24 h avant confirmation), `LECTURES_IG_PAR_JOUR` (200), table `lectures_profil` (`ab.note_lecture_profil`, `ab.lectures_profil`). Écran de fin `bravoBoutique` : une action (« Ajouter ma première offre », sinon « Annoncer ma boutique en stories » → `annonceStories`, assistant des stories pré-rempli, essai proposé en gratuit ; même bouton sur « C'est en vente » d'une offre). Création pas à pas complète (relancée par « ✨ Création pas à pas », `A.relance`) : toutes les questions d'abord, puis Virallink fabrique la boutique (`renduAssistantBoutique`, étapes `etapesBoutique`) : nom → adresse proposée à partir du nom, variante libre proposée si elle est prise (`?variante=1`) (crée la boutique en brouillon) → logo (ses couleurs : `palettes_photo`) → produits (`TYPES_NP` : e-book/fichier, produit sur un autre site, affiliation, séance, cadeau ; un écran par question, `A.np`, `NB_ECRANS_NP` ; fichier envoyé dans Virallink, nom tiré du fichier ; pour un lien (ou plusieurs, un par ligne : `N.lots`, une fiche à vérifier par produit, ajoutés d'un coup), `POST /api/boutique/importe_lien` → `import_lien.lit_page` lit la page (Open Graph, JSON-LD) et récupère nom, phrase, image et prix, sans IA, protégé contre les adresses internes ; enregistrés aussitôt par `ajouteProduitAssist`) → paiements si produit payant hors lien externe (« As-tu un compte Stripe ? » : relier ou créer via `/api/boutique/stripe`, état gardé dans `sessionStorage.vv_assist` pendant l'aller-retour, ou plus tard). Parcours en cours gardé sur le serveur (`/api/boutique/parcours`, `parcours.json` dans le dossier de la boutique, `gardeAssist`/`reprendAssist`/`oublieAssist`, copie de secours dans le navigateur) : reprise sur un autre appareil, via « Continuer ma boutique » ou « Ma boutique » → « Qui sont tes clientes ? » → « Tu les aides à quoi ? » → présentation : 3 propositions écrites par Virall.ai (`POST /api/boutique/bio` → `boutique_ia.bios` → `ia.ecrit_bios`, modèle léger, file `FILE_STUDIO`, option `ia` ; sans droit ou en cas d'échec, phrases toutes faites `biosModeles`), « Autres propositions », retouchable → réseaux → 3 propositions de design avec la vraie page (`propositionsDesign` : maquettes soignées `MAQUETTES` — Essentiel, Boutique, Moderne, Élégant : en-tête minimal, logo à sa taille, cartes produits propres, sans décor — habillées des couleurs du logo puis de `PALETTES_CHOISIES` ; `designProposition` → `A.design`, utilisé pour l'aperçu et la mise en ligne ; navigation « ← Précédentes » / « Autres → » et rappel de la boutique choisie ; logo enregistré dans la page dès l'envoi) → mise en ligne. Avant la création, `/api/boutique/apercu` part de `page_initiale` et les images passent par `/api/boutique/i/<nom>` ; produits d'exemple `PRODUITS_EXEMPLE` dans l'aperçu seulement. Dans l'éditeur, carte « Prochaine étape » (`majSuite`, `etapesBoutiqueRestantes` : produit → contenu à livrer → paiements si produit payant hors affiliation → mise en ligne → « Boutique prête », refermable), recalculée à chaque enregistrement.
- Plusieurs boutiques par compte : identifiant de boutique « bid » = id de l'utilisatrice pour la première (dossier `boutique/`), `"<uid>-<n>"` pour les suivantes (dossier `boutiques/<n>/`), stocké dans la colonne uid de la table `boutiques` (`bq.proprio`, `bq.bid_propre`, `bq.boutiques_de`, `nouvelle_boutique`, `supprime_boutique`). Boutique ouverte dans l'éditeur : `session["bq"]` via `bq_active()` (toutes les routes `/api/boutique*` l'utilisent) ; tout ce qui concerne la propriétaire (droits, profil, notifications, usage) passe par `bq.proprio(bid)`. Boutiques gratuites, 20 par compte quelle que soit la formule (décision de Mohamed) : `boutiques: 20` dans `plans.yaml` (`max_boutiques`). API `/api/boutiques` (liste), `/ouvrir`, `/nouvelle` (400 au-delà du plafond), `DELETE /api/boutiques/<bid>` (toute boutique, la première comprise : page, produits, inscrites et ventes effacés, adresse libérée ; la cliente repart de la création pas à pas). Écran « Mes boutiques » : `mesBoutiques()` ; une nouvelle boutique démarre par la création pas à pas.
- Parcours « Ajouter une offre » (`nouvelleOffre`, `assistantOffre`, état `BQ.offre`, dans l'onglet Produits, classe `en-offre` qui masque l'en-tête de l'éditeur) : une offre = le produit + sa présentation, mis en ligne d'un seul geste. Écrans : comment tu la vends (`MODES_OFFRE` : fichier, séance, affiliation, cadeau gratuit) → nom, prix, image, fichier ou lien → présentation (page de vente conseillée, quiz, fiche simple ; page de vente et quiz réservés aux formules avec `tunnels`) → aperçu et « Mettre en vente » (`metEnVente` : produit + tunnel + bloc produits + boutique en ligne, puis envoi du fichier) → « C'est en vente » (relier Stripe si besoin). Page de vente écrite par Claude (`POST /api/boutique/page_vente` → `boutique_ia.page_vente` → `ia.ecrit_page_vente`, file `FILE_STUDIO`, quotas `ia` + `tunnels`) posée sur le modèle `vente_formation`/`vente_accompagnement` ; sans droit, le modèle pré-rédigé reste. Ajouter une page de vente à un produit existant : `pageVenteProduit` (bouton de la fiche produit). L'onglet Tunnels n'existe plus : les tunnels s'ouvrent depuis leur produit (`editeTunnel`, « ← Mes produits ») ; une page de vente est en ligne dès que son produit est visible (`bq.tunnel_en_ligne`). Liste des produits avec état « ✓ En vente » / « ⚠️ Il manque… ». La création pas à pas de la boutique crée elle-même les produits ; « Ajouter une offre » sert ensuite (page de vente, quiz). Accueil : Crée ta page → Ajoute ta première offre → Partage ton lien (`prets` dans `boutique_etat`).
- `tunnels.py` : tunnels de vente de la boutique, réservés aux formules payantes (option `tunnels`, coupée dans `gratuit`). Deux types : quiz-audit noté (questions notées 0-4 par critère → note /100 et /20 par critère, point bloquant, actions prioritaires, e-mail facultatif, niveaux, offre) et page de vente (promesse, problème, bénéfices, contenu, témoignages réels seulement, à propos, FAQ, offre). ## Règles
- UX (`static/index.html`) : principe « un écran = une action » : une question ou un bouton principal par écran, pas d'encadré d'explication (`guide()` ne renvoie plus rien), détails rangés derrière « Filtres » ou « Voir plus ». Accueil « Aujourd'hui » (`renduAccueil`) : une carte avec une seule action (l'étape en cours du parcours boutique → tendances/veille → plan du mois → créer → publier, `etapesP` ; boutique : créer, terminer, première offre, que l'on peut remettre à plus tard `vv-offre-plus-tard`), le parcours sur une ligne de pastilles (`.parcours-ligne`), « Ce qui cartonne dans ta niche » (3 publications de `/api/tendances`) et « Ta boutique cette semaine » ; état relu quand la boutique a changé (`S.etatPerime`). Sur téléphone, toute création guidée (boutique, offre, page de vente, messages, plan du mois, stories) passe en plein écran : classe `html.en-parcours` posée par `majParcours()` (observateur de `main`), question en haut, bouton collé en bas, croix `#as-fermer` qui garde le parcours de la boutique. Sur téléphone, 5 onglets en bas (« Moi » regroupe résultats, profil, comptes, abonnement via `groupes()`). L'onglet de la galerie s'appelle « Tendances » ; bibliothèque active : deux onglets « Ce qui cartonne » (tendances) / « Prêtes pour toi » (sélection réécrite du lundi) (`majOngletsReels`, masqué en gratuit sans veille) ; « Nouvelle veille » et le menu des veilles seulement pour qui suit ses propres comptes (`veillePerso` : bibliothèque coupée, option `comptes_perso`) ; sans sélection : « Ta sélection arrive chaque lundi » + « Préparer ma sélection maintenant » ; le planning est rangé dans le Studio (`GROUPES.studio`, onglet « Mon planning » seulement s'il y a des publications planifiées) (décision de Mohamed, 10 novembre 2026). Studio : « Que veux-tu créer ? » en quatre tuiles (`tuilesStudio` : plan du mois, carrousel, Reel, stories) puis « Mes créations ». Éditeur de boutique : lien, état en ligne et aperçu visibles, le reste (QR, Mes boutiques, Nouvelle boutique, refaire pas à pas, Mode avancé) dans le menu « ⋯ » `.bt-menu` ; bouton « Aperçu » en bas à droite. Suppressions avec `toastAnnuler(...)` plutôt que `confirm()`, chargements avec `squelette()`, boutique en mode simple par défaut (classe `avance` pour les options cachées, `BQ.avance`).
- Ne jamais committer `.env`, `data/`, `rapports/`.
- Coûts : plafond mensuel `budget_usd` par formule (`plans.yaml`, vérifié dans `abonnements.peut` sur `usage.cout_usd`) ; coût IA calculé selon le modèle (`ia._compte`, `PRIX_MODELES`), classements sur le modèle léger (`MODELE_LEGER`). Pas de repli vers le collecteur Instagram standard (54× plus cher) sauf `APIFY_SECOURS=1` ; découverte par hashtags coupée sauf `DECOUVERTE_HASHTAGS=1` (3 hashtags, 20 posts max). Veille : seules les `adaptations_auto` (7) meilleures publications sont adaptées d'office (`moteur.a_adapter_d_office`), les autres du planning le sont à la demande (« à adapter », bouton `data-adapter`). Veille automatique du lundi en traitement différé à moitié prix (`ia.adapte_tous_differe`, Batch API ; file libérée pendant l'attente via `FIL.verrou`, lot mémorisé dans `lot_<aid>.json` ; `LOTS_DIFFERES=0` pour couper).
- Toute nouvelle consommation d'API doit respecter les quotas (`abonnements.peut`) et passer par la file de tâches. Elle exige aussi une adresse e-mail confirmée : `refus` (analyses/adaptations) et `reserve` (`ia`, `montage_reel`, `sequences_emails`) lèvent `AdresseNonConfirmee` → 403 `verification` (fenêtre « Confirme ton adresse » côté client). Lien signé `abonnements.jeton_confirmation` → `/confirmer` ; exigé seulement si les e-mails sont actifs ; adresses jetables refusées à l'inscription (`DOMAINES_JETABLES`).
- Reproduction d'un carrousel viral : le texte adapté (`slides_modele[].adapte`) est la traduction fidèle du modèle (mêmes chiffres, délais, mots forts, construction), seul le vocabulaire d'un autre métier change ; le Studio le reprend tel quel (`IA.carrousel` sans `tunnel`). Images : là où le modèle en a une ; carrousels du plan du mois : une image sur chaque slide (`remplit_banque(toutes=True)`).
- Les textes générés ne doivent pas « sonner IA » ; respecter les interdits de la niche de chaque client.
